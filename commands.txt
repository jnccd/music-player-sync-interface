Update MusicPlayerAvaloniaPort
The Avalonia port applies its own migrations on startup (DbWrapperService.EnsureDatabaseUpToDate), so
"dotnet ef database update" is normally no longer needed to run it - neither locally nor in
start_desktop_app.sh. The database no longer lives in the build output but in the app's data directory:
Linux:   $XDG_DATA_HOME/MusicPlayerAvaloniaPort-<Debug|Release>   (~/.local/share/... by default)
Windows: bin/<Debug|Release>/net10.0/Persistence
If you do run EF tooling by hand (e.g. "migrations add", or "database update" for a database that was
never opened by the app), pass MUSIC_PLAYER_DATA_DIR: under the EF tools the entry assembly is the tool
itself, so the executable-adjacent default would resolve to the tool's own directory. On Linux the XDG
default already matches the app, so only the suffix has to line up with your build configuration.
Linux:   DB_PROVIDER=sqlite MUSIC_PLAYER_DATA_DIR="$HOME/.local/share/MusicPlayerAvaloniaPort-Release" dotnet ef database update
Windows: DB_PROVIDER=sqlite MUSIC_PLAYER_DATA_DIR=./bin/Release/net10.0/Persistence dotnet ef database update
